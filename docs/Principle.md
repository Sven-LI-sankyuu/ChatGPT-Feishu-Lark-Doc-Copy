# ChatGPT 飞书富文本复制：业务与开发原则

本文档集中定义插件长期保持稳定的业务行为、数据结构和开发边界。新增交互、转换规则或页面适配时，应先检查是否符合这些原则，再增量补充本文档。

## 用户可见行为

插件只在每条 ChatGPT 助手回复的原生操作栏中增加一个“复制飞书文档版”图标按钮。按钮读取相邻官方复制按钮的实际颜色与透明度，使默认对比度保持一致，并在悬停和键盘聚焦时提高可见度。提示气泡挂在页面顶层并显示在按钮下方，避免被操作栏裁切；点击成功后显示“已复制飞书文档版, 去粘贴吧~”。

ChatGPT 自带的复制按钮、文本选区复制、代码块复制和浏览器剪贴板接口必须保持原样。插件不得重写 `navigator.clipboard`，不得拦截页面的 `copy` 事件，也不得阻止原生按钮的点击事件。用户点击飞书按钮时，插件允许程序化调用相邻的官方复制按钮一次，以取得 ChatGPT 为该回复生成的 Markdown；官方按钮可能显示自身的原生复制反馈，但其独立点击行为和输出不被插件修改。

一次点击只复制按钮所属的那条助手回复。找不到明确的助手回复正文或剪贴板写入失败时，插件应显示失败状态并记录可诊断错误，禁止用不完整内容伪装成功。

## 复制内容

剪贴板只写入 `text/plain` Markdown。2026 年 8 月 6 日的真实飞书验收确认 Markdown 整体基本可解析；同内容的 `text/html` 会被飞书当作普通文字显示标签，因此生产路径禁止携带 HTML 格式。

| 内容 | Markdown 输出 |
|---|---|
| 标题 | `#` 至 `######` |
| 段落与换行 | 块之间使用单个换行，不产生飞书可见的空白段落；代码块和公式内部换行原样保留 |
| 强调与删除 | `**`、`*`、`***`、`~~`；对应粗体、斜体、粗斜体与删除线 |
| 列表与引用 | Markdown 列表与 `>` |
| 代码 | 反引号与围栏代码块 |
| 表格 | Markdown 管道表格 |
| 超链接 | `[文字](地址)`，真实插件测试已识别为可点击链接 |
| 行内公式 | `$LaTeX$` |
| 独立公式 | 独立的 `$$` 块，当前飞书未自动居中 |

生产复制路径以 ChatGPT 官方复制结果为内容来源。官方结果中的 `\[...\]` 或独占行 `[...]` 转换为 `$$` 块，`\(...\)` 和带有明确 LaTeX 特征的括号变量转换为 `$...$`。代码围栏和行内代码不参与公式转换。页面 DOM 转换器只用于兼容性测试；无法确认官方复制结果时本次复制必须失败，禁止把 KaTeX 视觉字符写成普通文本后伪装成功。

ChatGPT 官方复制会把公式中独占行的 `=` 与 `-` 按 Markdown 标题语法输出为重复等号或 `## 表达式`。转换器只在已经确认的公式块内部恢复这些符号：重复等号恢复为单个等号，`## 表达式` 恢复为表达式后的减号；正文中的真实标题不参与该规则。

独立公式的开始定界符、LaTeX 内容和结束定界符在 Markdown 中使用换行分隔。真实验收确认飞书能识别公式但不会自动居中；飞书原生居中公式的 `text/plain` 仍只有 `$$formula$$`，居中信息只存在于包含页面、记录、块和作者标识的未公开 HTML 内部结构中。本版保留靠左公式，需要时由用户在飞书中手动居中；插件不得伪造飞书内部记录，也不得用固定空格或固定 LaTeX 间距伪造居中。

飞书把 Markdown 块之间的空行转换成真实空白段落，因此默认输出采用紧凑排版：标题、段落、列表、引用、表格、代码块与公式块之间只保留一个换行。代码围栏与公式定界符内部属于内容区域，其中的空行和换行不得被全局正则压缩。

## 设置与默认配置

设置页面面向需要固定团队排版规范、适配不同文档平台或调整公式规则的客户。默认配置必须在首次安装后直接可用；页面文字优先描述粘贴后的效果，高级区域再显示 Markdown 定界符等技术细节。当前版本先固化默认行为，设置页面在后续版本实现，禁止加入无法改变复制结果的占位控件。

设置采用“配置方案 + 具体选项”两层结构。普通用户选择“飞书紧凑”“标准 Markdown”或已保存的自定义方案；高级用户在自定义方案内调整空行和公式定界符。飞书紧凑方案始终是默认值，也是恢复默认设置后的结果。

| 配置字段 | 默认值 | 客户可见含义 |
|---|---|---|
| `schemaVersion` | `1` | 配置结构版本，用于升级迁移，不在普通界面显示 |
| `profile` | `feishu-compact` | 飞书紧凑、标准 Markdown 或自定义 |
| `spacing.blockBlankLines` | `0` | 标题、段落、列表、表格等内容块之间保留几个空白段落 |
| `formula.inlineDelimiter` | `dollar` | 行内公式使用哪组开始与结束标记 |
| `formula.blockDelimiter` | `double-dollar-lines` | 行间公式使用哪组独立定界符及换行方式 |
| `content.linkStyle` | `markdown` | 超链接保留为可点击文字，或显示文字与完整地址 |

公式定界符优先提供经过真实粘贴验收的预设。自定义定界符放在高级设置中，保存前必须检查开始与结束标记、行内换行限制和冲突字符，并通过即时预览明确展示最终剪贴板文本。未经验证的选项需要标注兼容性状态，禁止把“可能有效”写成“飞书支持”。

设置页面使用浏览器原生扩展选项页，由扩展详情页进入。页面包含配置方案、排版密度、公式、链接、即时预览、保存和恢复默认值；控件按任务分区平铺，避免嵌套卡片。预览样本固定覆盖两级标题、两个段落、行内公式、行间公式、表格和超链接，客户能在保存前看到空行与定界符的实际文本结果。

设置实现后使用 `chrome.storage.sync` 保存非敏感配置，使同一浏览器账号下的设备可以同步，不连接项目自建服务器。内容脚本读取并严格校验一份不可变配置快照，再将它显式传给转换器；`storage.onChanged` 只更新后续复制使用的配置，不修改已经写入剪贴板的内容。首次安装或字段缺失时补齐版本化默认值；已有配置无法迁移或字段非法时停止本次复制并引导用户打开设置页面，禁止静默回退后伪装成功。

```mermaid
flowchart LR
    A[扩展设置页] --> B[校验与即时预览]
    B --> C[chrome.storage.sync]
    C --> D[内容脚本读取配置快照]
    D --> E[转换器按配置生成文本]
    E --> F[剪贴板]
```

设置功能的自动测试必须覆盖默认配置快照、每个预设方案、允许的自定义边界、非法配置正确失败、保存后重新读取、旧版本迁移和恢复默认值。浏览器测试需要证明设置变更会改变下一次复制结果，并且不会改变 ChatGPT 官方复制按钮。

## 数据流

```mermaid
flowchart LR
    A[用户点击飞书按钮] --> B[调用相邻官方复制按钮]
    B --> C[读取官方 Markdown]
    C --> D[转换公式定界符]
    D --> E[移除非必要空行]
    E --> F[navigator.clipboard.writeText]
    F --> G[飞书粘贴]
```

内容脚本负责发现回复操作栏、注入按钮、取得官方复制结果、调用转换器和写入剪贴板。转换器只处理文本，不修改 ChatGPT 正文。CSS 只作用于带 `data-feishu-copy-*` 标记的插件节点，避免污染页面样式。按钮写入当前扩展版本的不可见 `data-feishu-copy-version` 属性，自动测试和人工排障可据此确认浏览器实际加载的版本。

## 页面适配边界

按钮必须锚定在已确认属于助手回复的原生回复复制按钮旁边。页面结构变化导致无法同时确认助手正文和原生操作栏时，本轮不注入按钮，并等待后续页面变化重新检查。

页面使用动态渲染，因此通过 `MutationObserver` 监听新增内容，并合并同一轮变化中的重复扫描。每个原生复制按钮最多对应一个插件按钮，重复执行初始化不得产生重复按钮。

## 安全与隐私

插件只在 `chatgpt.com` 和 `chat.openai.com` 本地运行，不发送聊天内容，不加载远程代码，不记录分析数据。`clipboardRead` 和 `clipboardWrite` 权限用于用户主动点击飞书按钮后的单次处理：读取刚刚由官方按钮生成的文本，再写入飞书版本；插件不得定时读取、后台监听或保存剪贴板内容。

转换前使用允许列表保留语义节点，只读取链接地址、表格跨行跨列和有序列表起始值等必要属性。脚本、样式、表单、媒体和页面交互元素不进入 Markdown；链接只允许 `http`、`https`、`mailto` 和页面内锚点。

## 飞书兼容性基线

2026 年 8 月 6 日的真实 ChatGPT 到飞书测试与验收样本确认：一级至五级标题、行内与独立公式、表格、超链接、基础粗体、基础斜体、下划线和删除线均可识别。独立公式保持靠左，需要用户手动居中。粗斜体组合与行内代码在不同飞书样本中的识别结果不一致，0.1.0 保留现有 Markdown 输出并记录为已知限制，后续根据专项最小测试调整。转换器继续用相邻及嵌套组合测试防止这些 Markdown 标记在代码层面丢失。
